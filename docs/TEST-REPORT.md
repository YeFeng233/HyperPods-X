# HyperPods-X 真机联调与测试记录

适配基线详见 [DEVICE-BASELINE.md](DEVICE-BASELINE.md)。本文档记录各功能迭代在目标真机（Xiaomi 17 Pro Max / HyperOS 4）及耳机（AirPods 5 / AirPods Pro 3）上的联调与验收结果。

## 0.5.0 架构重构与状态中心验收（2026-10-29）

完成将扫描与状态中枢迁入小米蓝牙宿主（`com.xiaomi.bluetooth`）状态中心（Hub）的重构验证：

### 1. 宿主状态中心机制与生命周期
- **熄屏扫描策略**：HyperOS 熄屏时会挂起普通应用的 BLE 扫描，仅保留蓝牙系统 UID；Hub 采用前台过滤扫描与动态重置机制，保障息屏与亮屏切换时广播接收不中断。
- **持久化与灾难恢复**：强杀小米蓝牙宿主后，Hub 可在 0.5 秒内自动重建，并由持久化 Keystore 密钥恢复广播解密；杀掉安全中心进程后，负一屏小组件仍能正常获取 Hub 聚合电量。
- **AACP 会话抢占防护**：当 HyperPods-X 应用存活时，Hub 自动协同系统蓝牙通道，避免系统原生通道抢占耳机设置的回报流。

### 2. 自动化测试与门禁验证
- **测试覆盖**：协议模块 101 项、通信模块 9 项、应用层 98 项，共计 **208 项单元测试全部通过（0 失败、0 错误）**；
- **静态检查**：Android Lint 0 错误；
- **构建规范**：R8 代码混淆优化完成，通过 APK v2 签名与 16 KB 页面对齐校验。

## 0.4.10 开盖自动回连与稳定性修复（2026-10-28）

- **开盖音频回连**：修复此前原生提示组件拦截 `CachedBluetoothDevice.connect(true)` 导致 A2DP/HFP 音频 profile 未及时拉起的问题；恢复系统原生回连逻辑，实现开盖即自动连接音频。
- **开盖布局防重叠**：解决耳机出盒时系统控制器重复绘制“正在连接”导致与模块电量卡片重叠的异常，跳过冗余的原生连接过渡层。
- **控制通道看门狗**：针对偶现的“L2CAP 通道建立后握手无回包”问题，加入 5 秒看门狗重试机制，超时自动断开并指数退避重建，最快 0.6 秒内恢复通信。

## 0.4.9 双界面支持与融合设备中心（2026-10-28）

- **双界面自由切换**：成功接入基于 Glasmio 的 iOS 拟态界面（`ui/ios/`），在“更多设置”中支持 miuix 与 iOS 实时无缝切换，持久化保存并在重启后恢复；SF Pro 字体渲染正常。
- **融合设备中心卡片**：
  - 勾选 `com.milink.service` 作用域后，系统控制中心的耳机卡片完整接入已绑定 AirPods；
  - 替换系统默认单调图标为对应型号的高清耳机渲染图；
  - 四档聆听模式（关闭/通透/自适应/降噪）按键与系统空间音频开关操控顺畅，状态回读平稳更新。
- **模块热重载与进程管理**：支持 libxposed API 102 热重载，覆盖安装时自动清理旧代监听并热替换；支持从 App“更多设置”一键授权 Root 优雅重启系统设置、小米蓝牙与设备互联宿主。

## 0.4.8 系统蓝牙列表入口直达（2026-10-28）

- **入口无缝挂接**：在系统设置的蓝牙设备列表中，接管已绑定 AirPods 卡片右侧的详情箭头（`preference_detail`），点击直接打开 HyperPods-X 设置；
- **隔离与安全性**：未绑定的 AirPods 或其他品牌蓝牙设备不受任何影响，继续执行系统原有逻辑；系统蓝牙详情页内的“HyperPods-X 高级设置”入口继续保留。

## 0.4.6 - 0.4.7 超级岛优化与连续自适应滑条（2026-10-28）

- **超级岛单耳分离展现**：针对超级岛组件裁切出独立的左右单耳高清素材，左侧显示左耳图标及电量，右侧显示右耳电量及图标，彻底去除多余留白；
- **自适应降噪连续调节**：接入连续滑杆算法，自适应降噪幅度支持 0～100 整数连续调节，支持滑动动态提交与串行防抖队列。

## 0.4.3 - 0.4.5 空间音频三档与对话感知（2026-10-26）

- **空间音频三档联动**：
  - 首页与二级页统一提供“关闭 / 固定 / 头部追踪”三档选择；
  - 头部追踪成功接入 `devmotion6` 动态姿态流，SensorService 生成系统级 `android.sensor.head_tracker` 节点，声场跟随头部转动实时渲染。
- **对话感知音轨调优**：
  - 监听耳机 `0x4B` 对话触发事件，在小米蓝牙宿主内通过 `VolumeShaper` 对当前输出到耳机的媒体音轨应用平滑音量包络（淡入 200ms，淡出 300ms）；
  - 避开系统全局音频焦点的暴力打断，完美兼容 HyperOS 的多应用同时发声设置。

## 0.4.1 - 0.4.2 智能入耳检测与提示音控制（2026-10-22）

- **入耳状态机**：
  - 支持摘下单耳暂停媒体、重新入耳继续播放；
  - 严格限制“仅自动恢复由本应用触发的暂停”，用户手动暂停的内容绝不误播放。
- **提示音量下限适配**：
  - 实测验证 AirPods 5 固件对提示音量的有效取值区间为 **15 ～ 100**，修正了早期界面允许设置低于 15 导致耳机固件静默拒绝的问题。
