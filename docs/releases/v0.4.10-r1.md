## HyperPods-X 0.4.10 修订版 1

本次加入日志导出、模块热重载和手动重启作用域。应用版本保持 `0.4.10-dev-device-test` / code 20，使用独立的 `v0.4.10-r1` 标签发布对应源码与安装包，可覆盖安装此前的同签名测试版。

- **导出日志**：miuix 与 iOS 的“更多设置”均可保存 ZIP，包含应用运行历史、诊断状态和已响应宿主的模块日志；地址、密钥等敏感字段经过脱敏。未响应的宿主会在收集状态中说明。
- **模块热重载**：支持 API 102 框架在更新时卸载旧实例并加载新代码，清理接收器、监听、任务和音频接口，重新绑定已打开的耳机卡片。有正在使用的音频会话时可拒绝卸载，结果写入日志。真机连续 4 次覆盖安装成功，相关宿主 PID 保持不变。
- **重启作用域**：“更多设置”新增手动入口，需要 Root 授权。只处理当前已授权的系统设置、小米蓝牙和设备互联；蓝牙与设备互联后台进程恢复后，重新打开系统页面即可。设置进程下次打开时加载模块。真机已验证，系统蓝牙栈与 system_server 保持原 PID。
- **整理设置入口**：删除重复的“系统蓝牙入口”授权行，保留“系统蓝牙设置”。三个作用域统一从“启用系统适配”（iOS 风格为“系统原生适配”）申请。

从不支持热重载的旧版升级或首次启用时，仍需重新加载宿主，可使用新增的“重启作用域”。热重载只更新模块代码；系统此前识别错误的耳机卡片仍可能需要重新进入设备互联。

App 与协议共 **159 项测试通过**，Android lint **0 错误、19 条提醒**，R8 优化构建和签名验证通过。当前真机验证范围为 Xiaomi 17 Pro Max、HyperOS 4、AirPods 5，要求 Android API 37 和支持现代 API 102 的 LSPosed。

附件提供项目原有签名的 APK、对应提交的源码 ZIP、`build-info.json` 和 `SHA256SUMS`。详细验证记录见仓库的 `docs/TEST-REPORT.md`。
