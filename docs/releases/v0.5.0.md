## HyperPods-X 0.5.0 — 重大升级

> **本次更新为重大升级。建议 fork 项目停留在 `0.4.10-r1`（Git 标签 `v0.4.10-r1`）。**
>
> 0.5.0 重构了蓝牙状态、扫描、开合盖检测和原生提示的承载方式，新增 `core/wire` 模块，并调整进程间通信、密钥保存与热重载生命周期。维护 fork 的开发者请先阅读[宿主状态中心迁移计划](https://github.com/YeFeng233/HyperPods-X/blob/v0.5.0/docs/HOST-HUB-MIGRATION-PLAN.md)，完成相应适配和回归后再跟进新架构。

### 2026-10-29 同版本更新

- 补齐 Apple 官方列出的全部 9 个 AirPods 5 / AirPods Pro 3 耳机型号：AirPods 5 普通版 `A3531/A3532/A3533`、无线充电盒版 `A3439/A3440/A3441`，以及 AirPods Pro 3 `A3063/A3064/A3065`。App 与系统宿主共用型号表，图片、设备中心控制、空间音频和设置入口统一识别这些型号；具体功能仍以设备实际回读为准。
- 保留 `0.5.0` 版本及现有 Release 地址，versionCode 从 **21** 提升至 **22**，使用原有签名重新打包，可覆盖安装同签名旧包。APK、源码 ZIP、`build-info.json` 与 `SHA256SUMS` 一并更新。
- 本次按维护者要求不运行单元或真机测试，也未单独运行完整 Android lint；仅执行优化构建（保留构建自带的 `lintVital` 检查）、APK 签名与对齐检查。下方 208 项测试和完整 lint 结果属于 0.5.0 首次发布，不作为本次补包的测试结果。型号依据见 [Apple 官方识别页](https://support.apple.com/zh-cn/109525)及[融合设备中心说明](https://github.com/YeFeng233/HyperPods-X/blob/v0.5.0/docs/NATIVE-FUSION.md)。

### 本次更新

- 合并 zyl6932 的 PR #2：将 BLE 扫描、广播解析、电量合并、开合盖检测、原生弹窗、超级岛和小组件状态迁入持久运行的小米蓝牙宿主 `com.xiaomi.bluetooth`。应用退出时，已绑定耳机的这些宿主功能仍可继续运行；AACP 控制、入耳联动、对话感知与头部追踪仍由应用负责。
- 新增带协议版本和调用方 UID 校验的 Binder 状态中心，使用进程死亡通知代替心跳。耳机身份密钥在宿主的设备保护存储中使用 Android Keystore 加密，宿主重启后可恢复广播解码。
- 支持 AirPods 5 与 AirPods Pro 3 的型号识别、独立图片和原生控制；改进实时开合盖响应、合盖弹窗收回和开盖自动回连。
- 拆分 AACP 控制会话与写入策略，修复握手后无回包的通道恢复，并在应用运行时避免系统 AACP 通道抢占耳机设置回报。
- 保留 miuix / iOS 双界面、日志导出和手动重启作用域，新增按宿主进程显示 Hook 安装结果的诊断。
- 修复状态中心重连重试可能取消自身的问题；发布流水线与打包校验新增 `core:wire` 测试。

### 升级与兼容性

- 应用版本为 `0.5.0-dev-device-test`，当前 versionCode 为 **22**，继续使用项目原有测试签名，可覆盖安装同签名旧版。
- **从 0.4.x 升级后，请在 LSPosed 中重新检查作用域并重启手机**，确保新状态中心及各宿主适配已加载。作用域包括系统设置 `com.android.settings`、小米蓝牙 `com.xiaomi.bluetooth`、设备互联 `com.milink.service` 和手机管家 `com.miui.securitycenter`。
- 应用需要附近设备与通知权限以保持控制会话，BLE 扫描不再由应用执行，也不再请求位置和扫描权限。
- 最低要求仍为 Android API 37、支持现代 libxposed API 102 的框架及相应 HyperOS 系统接口。这是预览版本，其他设备与系统组合需要单独验证。
