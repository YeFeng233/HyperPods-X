## 0.4.5 关闭、固定与头部追踪

日期：2026-10-26。用户已确认头追不影响耳机滑动调节音量，本版按新的界面要求将空间音频改为三选一；首页与空间音频二级页使用同一套控件和系统状态。

| 档位 | 实际行为 | 校准要求 |
| --- | --- | --- |
| 关闭 | 先停止姿态订阅与虚拟头部传感器，再移除此耳机的系统空间化偏好 | 无 |
| 固定 | 保留系统空间渲染，停止姿态与虚拟传感器，将系统期望头追模式设为禁用 | 无 |
| 头部追踪 | 启用系统渲染，取得真实耳机姿态，以当前朝向回中并创建系统头追会话 | 使用已保存的三轴校准 |

本轮同一真机的模式回读结果：

- 关闭：`compatible=false`、`enabled=false`、`nativeActive=false`、`motionActive=false`。

本轮检查模式切换、真实姿态订阅及清理，没有重做三轴动作或新增主观试听；动态听感沿用此前用户验收。固定/关闭是系统偏好，实际渲染仍受音轨和系统支持条件影响，不能把选中档位当作每个播放器都已空间化的证明。

## 0.3.1 真实姿态修复与验收

日期：2026-10-22，Asia/Hong_Kong；仍限于同一台 Xiaomi 17 Pro Max / HyperOS OS4.0.4.0.XPBCNXM 与同一副 AirPods 5 / A3441。

**真实耳机姿态已接入 HyperOS 头部追踪，三轴校准、动态试听与摘下双耳后的自动清理均通过本轮真机验证。** 这是手动启用的实验功能，尚未完成长时间漂移、功耗和各类中断场景的验收。

### 修复原因与实现

此前使用固定服务编号，只收到确认包。本次先读取 RTBuddy 的 SensorDataWX 服务描述，再按耳机实际公布的运动服务订阅：

1. 初始化 RTBuddy，使用 field 4 请求传感器描述；初始收到 service 12 `activity` 与 service 17 `HostLibHID`。
2. 在绑定耳机是当前 A2DP 输出、没有通话的情况下，临时请求 AACP control `0x06` 的控制会话。之后耳机公布受保护的 service **15 `devmotion6`**，MaxReportSize=191。
3. 以 **20,000µs** 周期订阅实际发现的 service 15；收到约 **50 Hz** 的真实四元数。UI 的平均速率包含初始化等待，短会话约为 46–48 Hz。
4. 生成每次请求的序号、长度和正确服务编号；停止订阅使用同一服务编号。修复未知 RTBuddy 描述帧导致同批后续姿态被丢弃的问题；将错误码 711 等失败回执与有效姿态分开。

控制 `0x06` 本身没有获得设备报告确认，不能仅因发送成功就显示“耳机已确认”。修复后的证据是服务 15 随后出现且持续输出姿态。原控制会话状态未知时，通过重建控制连接结束本次请求；若原值明确为 0，则恢复 0。后续新会话再次从只公布 service 12/17 开始，普通配置回读正常。

OS serialization 描述读取器限制长度、深度、对象数量和引用，只向应用暴露服务编号、名称和报告大小等元数据。原始描述可能含设备标识，不进入公开日志、测试固件样本或交付包。公开协议来源见 [第三方声明](../THIRD_PARTY.md)。

### 使用与限制

1. 佩戴并连接耳机，进入“空间音频”，保持“固定空间音频”开启。
2. 开启“姿态采样”，等待有效姿态出现。初次使用需完成三轴校准；这副耳机的本轮校准已保存。
3. 固定手机位置并正视手机，点击“正视手机并回中”，再开启“动态头部追踪”。
4. 可使用“正前方定位试听 20 秒”检查方向。关闭姿态采样会同时结束系统追踪；摘下双耳、断连后需手动重新启用。

诊断采样最长 5 分钟；启用动态追踪后持续采样，直到停止或发生中断。不会在开机、开盖、重连或重新佩戴时自动创建追踪传感器。普通电量、原生开盖弹窗和超级岛服务继续沿用既有实现，本轮未重复开盖硬件回归。

已验证真实姿态到系统渲染和人耳听感的基本闭环。尚未量化绝对转角精度、端到端时延、静止漂移、长期功耗或复杂运动表现；未逐项实测来电、切换音频输出、进程意外退出等故障清理。系统桥接已有相应路由/通话、800ms 租约及 Binder 死亡保护；本轮自动清理实测覆盖摘下双耳。

本 ROM 的发送 JNI 存在约 1° 量化，使用 HyperOS 的 HRTF 和“相对世界”模式；没有接入 Apple 个性化轮廓或手机姿态融合。手机位置改变后需要回中。

构建版本 `0.3.1-dev-device-test` / code 4。协议测试 **24 项通过、0 失败**；R8 优化包与 Android lint 均成功，lint 0 错误、17 条非阻断提醒。交付摘要见 [联调报告](TEST-REPORT.md)。下文保留 0.3.0 的历史记录，不能作为当前姿态能力的判断。

## 实现与入口

首页及耳机高级设置新增 Miuix“空间音频”页面，提供系统能力与当前路由状态、此耳机的固定空间音频开关、12 秒方向测试音，以及实验性的姿态采样、三轴校准、回中、动态追踪和系统桥接自检。

固定空间音频调用此设备的系统 Spatializer 偏好。动态通道复用现有 AACP 连接，经受校验的 Binder 接入 `com.xiaomi.bluetooth` 内的 `Spatialcontroller`，再使用本机 `libspatial.so` 创建 UHID 头部传感器。没有增加 LSPosed 作用域、改写全局 VendorID、修改系统库或更改 SELinux 模式。

姿态采样和虚拟传感器均须手动启动，不随开机、开盖或重连自动运行。动态追踪要求新鲜的真实姿态及针对该地址、型号和设备报告版本保存的三轴校准。当前未取得姿态，校准和动态追踪的可用条件未满足。

## 实现边界

- 测试音每个声道约 2 秒，低峰值、淡入淡出；使用 AudioTrack 局部音量，不调整系统媒体音量。先提交静音并核对实际路由，路由改变或通话时停止，页面提供停止按钮。
- AACP 姿态包按声明长度分帧，有限制的 protobuf 读取器识别已研究的服务布局；确认报文单独处理。四元数、三轴校准和坐标变换有边界测试，但尚无本副耳机真实姿态验证。
- Binder 引导入口受签名权限保护，每次事务检查实际调用 UID、绑定地址和协议接口；高频姿态使用 Binder，携带单调时钟时间戳及递增序号。过期、倒序、非有限数或越界向量被拒绝。
- 宿主仅在目标耳机为当前 A2DP 设备、无通话且无其他动态头部传感器时创建会话。设计有 800ms 姿态租约、Binder 死亡及路由/通话检查，结束时销毁虚拟设备并恢复先前追踪偏好；本轮实测覆盖自检正常结束的清理，尚未逐项注入所有故障。
- 本 ROM 的 JNI 创建返回值为错误标志：`false` 表示 UHID_CREATE 写入成功，`true` 表示打开或写入失败，已由库静态分析和真机创建核对。发送接口将输入截为整数角度后编码 HID，存在约 1° 量化；动态听感和时延尚未验证。
- 坐标、回中、三轴校准、漂移、真实运动的旋转方向与动态听感均待有效姿态流后验证。不得用静止自检数据替代耳机姿态，或把订阅回执记为动态追踪通过。

目前没有足够证据判断不输出姿态的具体原因。设备侧所有权、订阅条件及本型号的数据格式仍需研究；不能把更改 VendorID 或伪装 Pro 型号视为已证明的必要条件。
