# 空间音频与动态头部追踪技术方案与实测记录

HyperPods-X 实现了将 AirPods 内置的六轴运动姿态数据接入 HyperOS 系统的 Spatializer 空间音频渲染管线，支持固定空间音频与动态头部追踪。

---

## 1. 架构设计与三档模式

空间音频支持三种工作模式，设置项与当前运行状态全局同步：

| 模式 | 运行机制 | 传感器与系统行为 |
| --- | --- | --- |
| **关闭** | 关闭系统空间音频偏好 | 释放耳机姿态订阅，销毁虚拟头部追踪传感器 |
| **固定** | 开启 HyperOS 原生空间音频渲染 | 不采集头部姿态（固定声场朝向），无需校准 |
| **头部追踪** | 采集耳机实时姿态并驱动系统追踪器 | 需预先完成三轴校准，转头时声源始终锚定在空间绝对方位 |

---

## 2. 真实姿态采集与系统桥接原理

### 2.1 运动服务动态发现与订阅
- **服务发现**：AirPods 并非使用静态固定的服务 ID。模块通过 RTBuddy 接口查询 `SensorDataWX` 描述符，在 AACP 控制会话就绪后，动态定位到受保护的运动数据服务 **`devmotion6`（service 15）**。
- **高频采样**：以 **20 ms 周期（约 50 Hz）** 订阅耳机回传的高精度四元数（Quaternion）姿态流，确保动态追踪顺滑无卡顿。

### 2.2 三轴校准与正视回中
- **三轴校准流程**：引导用户依次执行“右转”、“抬头”、“右倾”三个动作，计算并构建当前用户的姿态空间基底矩阵，消除初始佩戴角度偏差。校准结果按设备物理地址持久化存储。
- **正视回中**：当用户坐姿或手机持握方向改变时，点击“正视手机并回中”将当前朝向重置为声场前方基准。

### 2.3 系统 SensorService 桥接
- 模块在系统底层创建并注入 `android.sensor.head_tracker(37)` 虚拟传感器节点；
- 将经过校准与坐标系变换后的旋转矢量（Rotation Vector）实时推送给 HyperOS 的音频渲染线程（`miSpatializer`），完成声场 HRTF 动态空间化。

在 Xiaomi 17 Pro Max（HyperOS 4, API 37）与 AirPods 5 / AirPods Pro 3 上的实机联调结果：

| 测试项目 | 验证结果 | 详细指标 |
| --- | --- | --- |
| **姿态数据流** | 通过 | 持续稳定接收 service 15 姿态回包，采样频率维持在 48～50 Hz |
| **三轴校准与复用** | 通过 | 矩阵正交性检验通过，应用重启与覆盖安装后均能稳定复用 |

| **摘耳与中断清理** | 通过 | 摘下双耳自动停止姿态订阅并注销头部追踪传感器，普通控制通道平稳恢复 |

## 4. 使用说明与注意事项

1. **首次启用**：佩戴好双耳后进入“空间音频”，开启“头部追踪”，跟随屏幕动画提示依次完成右转、抬头、侧倾动作；
2. **日常校正**：日常使用若出现声场轻微偏向，面对手机点击“正视手机并回中”即可瞬时归正；
3. **渲染依赖**：空间音频依赖 HyperOS 底层音频引擎渲染，需播放器与音源支持多声道或系统空间化格式。
